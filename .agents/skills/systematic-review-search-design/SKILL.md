# Search Design

## Workflow

1. Verify the M1-approved question, eligibility criteria, dates, languages, and
   information sources.
2. Build each strategy with controlled vocabulary, free text, spelling and
   abbreviation variants, proximity, fields, and justified limits.
3. Translate syntax per platform; never mechanically reuse one database string.
4. Test known eligible sentinel records and investigate misses.
5. Review every strategy with a PRESS-compatible peer-review record when
   appropriate; resolve comments transparently.
6. Save exact final strategies, platforms, interfaces, dates, and planned export
   formats as the M2 subject. Obtain human approval before production execution.

## Boundaries

- Do not add outcome terms merely to reduce retrieval unless the protocol
  explicitly requires them.
- Do not silently change eligibility criteria.
- Search quotations are syntax, not screening evidence.

When serializing shared artifacts, read [the contracts](../systematic-review/references/contracts.md); do not invent field names.

Finish `APPROVED` after M2. The next phase is search execution.
